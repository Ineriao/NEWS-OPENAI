# 新闻发布管理系统 - 开发文档

## 一、项目概述

新闻发布管理系统是一个模拟新闻媒介发布流程的 Web 应用，支持多角色权限管理。

### 核心功能模块
1. **登录/注册模块** - 游客访问、普通用户登录、后台登录
2. **前台信息浏览** - 首页展示、栏目页面、新闻详情、搜索、评论
3. **新闻编辑管理** - 分类管理、新闻增删改查
4. **新闻总编管理** - 新闻审核、发布、修改、存档
5. **信息管理** - 用户/编辑/总编/新闻/评论管理
6. **热搜展示** - 多平台热搜聚合、历史记录查询
7. **外部新闻** - 从多个新闻源获取并展示新闻

## 四、数据库设计

### 数据表概览
| 表名 | 说明 |
|------|------|
| user | 用户表（角色：1=普通用户, 2=编辑, 3=总编, 4=管理员） |
| category | 分类表（支持二级分类） |
| news | 新闻表（状态：0=草稿, 1=待审核, 2=已发布, 3=已存档） |
| comment | 评论表（支持回复） |
| hot_search | 热搜表（保存前10条，保留历史记录） |
| external_news | 外部新闻表（从 API 抓取的新闻） |
| news_like | 点赞表（用户-新闻点赞关系）[2024-12-15 新增] |
| news_collection | 收藏表（用户-新闻收藏关系）[2024-12-15 新增] |
| comment_like | 评论点赞表（用户-评论点赞关系）[2024-12-15 新增] |

### 定时任务 [2024-12-15 新增]
| 任务 | 周期 | 说明 |
|------|------|------|
| 热搜刷新 | 每30分钟 | 自动刷新微博/抖音/知乎/百度热搜 |

## 七、启动指南

### 环境要求
| 组件 | 版本 | 必需 |
|------|------|------|
| JDK | 17（必须，JDK 21+ 与 Lombok 不兼容） | ✅ |
| Maven | 3.6+ | ✅ |
| Node.js | 18+ | ✅ |
| MySQL | 8.0+ | ✅ |
| Redis | 5.0+（缓存服务）| ❌ 可选 [2024-12-22 更新] |
| Elasticsearch | 7.17.16（全文搜索）| ❌ 可选 [2024-12-22 更新] |

> **注意**：Redis 和 ES 为可选服务。未启动时系统自动降级：ES 降级到 MySQL LIKE 搜索，Redis 降级到无缓存模式。

### 启动步骤
1. **（可选）Elasticsearch**：启动 ES 服务，启用全文搜索
2. **（可选）Redis**：启动 Redis 服务，启用缓存加速
3. **一键启动**：运行根目录 start-all.bat（启动后端 + 热搜服务）[2024-12-22 更新]
4. **前端**：cd news-frontend && npm install && npm run dev

**或手动启动：**
- **后端**：cd news-backend && build.bat（构建后需手动运行 jar）
- **热搜服务**：cd DailyHotApi && npm install && npm run build && npm run start

## 十、Redis 缓存配置 [2024-12-16 新增]

### 缓存策略

| 缓存类型 | 缓存名称 | TTL | 说明 |
|----------|----------|-----|------|
| 分类缓存 | category | 1小时 | 分类数据很少变化，缓存时间较长 |
| 热搜缓存 | hotSearch | 30分钟 | 与定时刷新周期一致 |
| 新闻缓存 | news | 10分钟 | 新闻详情缓存 |
| 新闻列表缓存 | newsList | 5分钟 | 公开已发布新闻列表 [2024-12-16 新增] |
| 评论数缓存 | commentCount | 2分钟 | 评论数变化较频繁 |

### 缓存 Key 设计

```
category:tree                    # 分类树
hotSearch:{source}               # 热搜（微博/抖音/知乎/百度）
news:detail:{id}                 # 新闻详情
newsList:{categoryId}:{pageNum}:{pageSize}:{sortBy}:{sortOrder}  # 新闻列表 [2024-12-16 新增]
commentCount:{newsId}            # 评论数
```

### 缓存失效策略

| 操作 | 清除的缓存 |
|------|------------|
| 新增/修改/删除分类 | 清除所有分类缓存 |
| 刷新热搜数据 | 清除所有热搜缓存 |
| 新闻审核通过/存档/修改/删除 | 清除所有新闻缓存和列表缓存 |
| 发表/删除评论 | 清除对应新闻的评论数缓存 |

### 核心注解使用

```java
// 添加缓存
@Cacheable(value = "category", key = "'tree'")
public List<Category> getTreeList() { ... }

// 清除缓存
@CacheEvict(value = "category", allEntries = true)
public void delete(Long id) { ... }
```

```
├── redis-server.exe      # Redis 服务器

```

## 十一、浏览量异步更新 [2024-12-16 新增]

### 实现原理

将新闻浏览量从同步数据库更新改为 Redis 异步累积 + 定时批量同步。

```
用户访问新闻 → Redis INCR 累积增量 → 定时任务(每5分钟) → 批量同步到数据库
```

### Redis Key 设计

```
viewCount:delta:{newsId}    # 浏览量增量（如 viewCount:delta:1）
```

### 核心文件

| 文件 | 说明 |
|------|------|
| `service/ViewCountService.java` | 浏览量服务（Redis 累积、批量同步） |
| `service/impl/NewsServiceImpl.java` | getDetailAndView 使用异步更新 |
| `dao/NewsMapper.java` | incrementViewCountBy 批量更新方法 |
| `task/ScheduledTasks.java` | 每5分钟同步浏览量定时任务 |

### 性能对比

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| 每次访问数据库写 | 1次 UPDATE | 0次（写 Redis） |
| 数据库写频率 | 每次访问 | 每5分钟批量 |
| 浏览量延迟 | 实时 | 最大5分钟 |

### 配置说明

使用 springdoc-openapi 1.7.0，配置 JWT 安全认证。

```java
// OpenApiConfig.java
@Configuration
public class OpenApiConfig {
    @Bean
    public OpenAPI customOpenAPI() {
        return new OpenAPI()
                .info(new Info()
                        .title("新闻发布管理系统 API")
                        .version("1.0.0")
                        .description("新闻发布管理系统后端接口文档"))
                .addSecurityItem(new SecurityRequirement().addList("JWT"))
                .components(new Components()
                        .addSecuritySchemes("JWT", new SecurityScheme()
                                .type(SecurityScheme.Type.APIKEY)
                                .in(SecurityScheme.In.HEADER)
                                .name("Authorization")
                                .description("JWT Token")));
    }
}
```

| 用户认证 | 登录、注册、用户名检查 |
| 新闻管理 | 新闻的增删改查、审核发布等操作 |

4. 输入登录获取的 JWT Token
5. 即可测试所有接口
