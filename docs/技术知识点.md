## 一、JWT (JSON Web Token) 认证

### 1.1 什么是 JWT？

JWT 是一种开放标准（RFC 7519），用于在各方之间安全地传输信息。它是一个紧凑的、URL 安全的令牌。

### 1.2 JWT 的结构

JWT 由三部分组成，用点（.）分隔：

```
xxxxx.yyyyy.zzzzz
Header.Payload.Signature
```

#### Header（头部）
```json
{
  "alg": "HS256",    // 签名算法
  "typ": "JWT"       // 令牌类型
}
```

#### Payload（载荷）
```json
{
  "userId": 1,           // 自定义数据
  "username": "admin",
  "role": 4,
  "iat": 1702368000,     // 签发时间
  "exp": 1702454400      // 过期时间
}
```

#### Signature（签名）
```
HMACSHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  secret
)
```

### 1.3 JWT 认证流程

```
┌──────────┐                              ┌──────────┐
│  前端    │                              │  后端    │
└────┬─────┘                              └────┬─────┘
     │                                         │
     │  1. POST /api/auth/login               │
     │  {username, password}                   │
     │ ───────────────────────────────────────>│
     │                                         │
     │                          验证用户名密码 │
     │                          生成 JWT Token │
     │                                         │
     │  2. 返回 Token                          │
     │ <───────────────────────────────────────│
     │                                         │
     │  存储 Token (localStorage)              │
     │                                         │
     │  3. 请求其他接口                        │
     │  Header: Authorization: Bearer <token>  │
     │ ───────────────────────────────────────>│
     │                                         │
     │                    拦截器验证 Token 有效性
     │                    解析出用户信息        │
     │                                         │
     │  4. 返回数据                            │
     │ <───────────────────────────────────────│
```

### 1.4 本项目中的 JWT 实现

#### JwtUtil.java 核心方法

```java
// 生成 Token
public String generateToken(Long userId, String username, Integer role) {
    Map<String, Object> claims = new HashMap<>();
    claims.put("userId", userId);
    claims.put("username", username);
    claims.put("role", role);

    return Jwts.builder()
            .setClaims(claims)           // 设置载荷
            .setSubject(username)        // 设置主题
            .setIssuedAt(new Date())     // 设置签发时间
            .setExpiration(expiryDate)   // 设置过期时间
            .signWith(key, HS256)        // 签名
            .compact();
}

// 解析 Token
public Claims parseToken(String token) {
    return Jwts.parserBuilder()
            .setSigningKey(key)
            .build()
            .parseClaimsJws(token)
            .getBody();
}
```

#### JwtInterceptor.java 拦截器

```java
@Override
public boolean preHandle(HttpServletRequest request,
                         HttpServletResponse response,
                         Object handler) {
    // 1. 从请求头获取 Token
    String token = request.getHeader("Authorization");

    // 2. 移除 "Bearer " 前缀
    token = token.substring(7);

    // 3. 验证 Token
    if (!jwtUtil.validateToken(token)) {
        // 返回 401 未授权
        return false;
    }

    // 4. 将用户信息存入 request，供 Controller 使用
    request.setAttribute("userId", jwtUtil.getUserId(token));
    request.setAttribute("username", jwtUtil.getUsername(token));
    request.setAttribute("role", jwtUtil.getRole(token));

    return true;
}
```

### 1.5 JWT vs Session 对比

| 特性 | JWT | Session |
|------|-----|---------|
| 存储位置 | 客户端 | 服务器端 |
| 服务器压力 | 低 | 高（需存储会话） |
| 分布式支持 | 天然支持 | 需要共享会话 |
| 安全性 | 需要 HTTPS | 依赖 Cookie 安全 |
| 注销 | 较复杂（需黑名单） | 简单 |

## 四、前后端分离与跨域

### 4.1 为什么会有跨域问题？

浏览器的**同源策略**：协议、域名、端口必须完全相同，否则禁止访问。

```
前端: http://localhost:5173
后端: http://localhost:8080
```
↑ 端口不同，属于跨域

### 4.2 CORS (跨域资源共享)

通过设置 HTTP 响应头允许跨域：

```java
response.setHeader("Access-Control-Allow-Origin", "http://localhost:5173");
response.setHeader("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE");
response.setHeader("Access-Control-Allow-Headers", "Content-Type, Authorization");
response.setHeader("Access-Control-Allow-Credentials", "true");
```

### 4.3 预检请求 (Preflight)

对于复杂请求（如带 Authorization 头），浏览器会先发送 OPTIONS 请求：

```
1. 浏览器: OPTIONS /api/news (预检请求)
2. 服务器: 返回 CORS 头，状态 200
3. 浏览器: POST /api/news (实际请求)
4. 服务器: 返回数据
```

## 六、密码安全

### 6.1 为什么不能明文存储密码？

数据库泄露时，明文密码会直接暴露用户信息。

### 6.2 BCrypt 加密

```java
// 注册时：加密密码
BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();
String hashedPassword = encoder.encode("user123");
// 结果: $2a$10$N.zmdr9k7uOCQb376NoUnuTJ8iAt6Z5EHsM8lE9lBOsl...

// 登录时：验证密码
boolean matches = encoder.matches("user123", hashedPassword);
```

### 6.3 BCrypt 特点

- **单向加密**：无法从密文还原明文
- **加盐**：相同密码每次加密结果不同
- **慢速**：故意设计为慢速，防止暴力破解

## 八、数据库设计知识点

### 8.1 主键策略

- **自增 (AUTO_INCREMENT)**：简单，但分布式环境有问题
- **UUID**：全局唯一，但索引效率低
- **雪花算法 (Snowflake)**：分布式唯一ID，有序

### 8.2 外键约束

```sql
FOREIGN KEY (`category_id`) REFERENCES `category`(`id`)
```

- 保证数据完整性
- 可以设置级联删除/更新

### 8.3 索引优化

```sql
INDEX `idx_status` (`status`)          -- 经常查询的字段
INDEX `idx_publish_time` (`publish_time`)  -- 排序字段
```

### 8.4 自引用关系

分类表的二级分类、评论表的回复功能都用到了自引用：

```sql
CREATE TABLE `category` (
    `id` BIGINT PRIMARY KEY,
    `parent_id` BIGINT,
    FOREIGN KEY (`parent_id`) REFERENCES `category`(`id`)
);
```

## 十一、Java EE vs Jakarta EE (Servlet API 版本问题)

### 11.1 历史背景

2017 年，Oracle 将 Java EE 贡献给 Eclipse 基金会，由于商标原因，Java EE 改名为 **Jakarta EE**。

### 11.2 包名变化

| 版本 | 包名 | 说明 |
|------|------|------|
| Java EE 8 及之前 | `javax.servlet` | 传统命名 |
| Jakarta EE 9+ | `jakarta.servlet` | 新命名 |

### 11.3 Spring 框架兼容性

| Spring 版本 | 兼容的 Servlet API |
|-------------|-------------------|
| Spring 5.x | `javax.servlet` (Java EE) |
| Spring 6.x | `jakarta.servlet` (Jakarta EE 9+) |

### 11.4 常见错误

```
方法签名与父接口不匹配
```

**原因**：混用了不同版本的 Servlet API

**解决方案**：确保 Spring 版本与 Servlet API 版本匹配

```xml
<!-- Spring 5.x 使用 -->
<dependency>
    <groupId>javax.servlet</groupId>
    <artifactId>javax.servlet-api</artifactId>
    <version>4.0.1</version>
</dependency>

<!-- Spring 6.x 使用 -->
<dependency>
    <groupId>jakarta.servlet</groupId>
    <artifactId>jakarta.servlet-api</artifactId>
    <version>5.0.0</version>
</dependency>
```

## 十二、DTO / VO / Entity 分层设计

### 12.1 三者的区别

| 类型 | 全称 | 用途 | 方向 |
|------|------|------|------|
| **Entity** | 实体类 | 对应数据库表结构 | 数据库 ↔ 后端 |
| **DTO** | Data Transfer Object | 接收前端请求参数 | 前端 → 后端 |
| **VO** | View Object | 返回给前端的数据 | 后端 → 前端 |

### 12.2 为什么要分层？

#### 安全性
```java
// Entity 包含密码
public class User {
    private String password;  // 敏感信息
}

// VO 不包含密码
public class UserVO {
    // 没有 password 字段
}
```

#### 灵活性
```java
// DTO 可以包含确认密码
public class RegisterDTO {
    private String password;
    private String confirmPassword;  // 数据库不存储
}
```

#### 解耦
- 数据库结构变化不影响 API 格式
- 前端需求变化不影响数据库设计

### 12.3 实际示例

```
登录流程:
前端 → LoginDTO {username, password}
       ↓
    Service 处理
       ↓
后端 → LoginVO {token, userId, username, role}

用户查询:
数据库 → User {id, username, password, role, status...}
           ↓
       转换为 VO
           ↓
前端 ← UserVO {id, username, role, status}  // 无密码
```

### 12.4 命名规范

| 类型 | 命名规则 | 示例 |
|------|----------|------|
| Entity | 表名单数 | User, News, Comment |
| DTO | 功能 + DTO | LoginDTO, RegisterDTO, NewsCreateDTO |
| VO | 功能 + VO | LoginVO, UserVO, NewsDetailVO |

```java
public interface HandlerInterceptor {
```

### 13.3 JWT 拦截器实现要点

```java
@Override
public boolean preHandle(HttpServletRequest request,
                         HttpServletResponse response,
                         Object handler) {
    // 1. OPTIONS 请求放行（CORS 预检）
    if ("OPTIONS".equals(request.getMethod())) {
        return true;
    }

    // 2. 获取 Token
    String token = request.getHeader("Authorization");

    // 3. 验证 Token
    if (!jwtUtil.validateToken(token)) {
        // 返回 401
        return false;
    }

    // 4. 将用户信息存入 request
    request.setAttribute("userId", jwtUtil.getUserId(token));

    return true;  // 放行
}
```

## 十四、状态机模式（State Machine）

### 14.1 什么是状态机？

状态机是一种设计模式，用于管理对象在不同状态之间的转换。适用于有明确状态流转逻辑的业务场景。

### 14.2 新闻状态流转

```
┌─────────┐    提交审核    ┌─────────┐    审核通过    ┌─────────┐    存档    ┌─────────┐
│  草稿   │ ─────────────> │ 待审核  │ ─────────────> │ 已发布  │ ────────> │ 已存档  │
│  (0)    │                │  (1)    │                │  (2)    │           │  (3)    │
└─────────┘                └────┬────┘                └─────────┘           └─────────┘
     ↑                          │
     │        退回修改          │
     └──────────────────────────┘
```

### 14.3 状态常量定义

```java
public class News {
    public static final int STATUS_DRAFT = 0;       // 草稿
    public static final int STATUS_PENDING = 1;     // 待审核
    public static final int STATUS_PUBLISHED = 2;   // 已发布
    public static final int STATUS_ARCHIVED = 3;    // 已存档
}
```

### 14.4 状态转换方法

```java
// 提交审核（编辑操作）
public void submitForReview(Long newsId, Long operatorId) {
    News news = newsMapper.selectById(newsId);

    // 验证当前状态
    if (news.getStatus() != News.STATUS_DRAFT) {
        throw new RuntimeException("只有草稿状态的新闻可以提交审核");
    }

    // 验证权限
    if (!news.getAuthorId().equals(operatorId)) {
        throw new RuntimeException("只能提交自己的新闻");
    }

    // 状态转换
    news.setStatus(News.STATUS_PENDING);
    newsMapper.updateById(news);
}

// 审核通过（总编操作）
public void approve(Long newsId, Long reviewerId) {
    News news = newsMapper.selectById(newsId);

    if (news.getStatus() != News.STATUS_PENDING) {
        throw new RuntimeException("只有待审核的新闻可以审核");
    }

    news.setStatus(News.STATUS_PUBLISHED);
    news.setReviewerId(reviewerId);
    news.setPublishTime(LocalDateTime.now());
    newsMapper.updateById(news);
}
```

### 14.5 设计要点

1. **状态常量化**：使用常量定义状态，避免魔法数字
2. **状态校验**：每次转换前验证当前状态是否允许
3. **权限控制**：不同角色只能执行特定的状态转换
4. **审计记录**：记录操作人和操作时间

### 15.3 自定义 SQL 分页

```java
// Mapper 接口
@Select("""
    SELECT n.*, c.name as category_name, u.username as author_name
    FROM news n
    LEFT JOIN category c ON n.category_id = c.id
    LEFT JOIN user u ON n.author_id = u.id
    WHERE n.status = #{status}
    ORDER BY n.publish_time DESC
    """)
IPage<NewsListVO> selectNewsPage(Page<NewsListVO> page, @Param("status") Integer status);

// Service 层调用
Page<NewsListVO> page = new Page<>(pageNum, pageSize);

```

### 15.4 分页结果封装

```java
@Data
public class PageVO<T> {
    private List<T> records;      // 当前页数据
    private long total;           // 总记录数
    private long pages;           // 总页数
    private long current;         // 当前页码
    private long size;            // 每页大小

    public static <T> PageVO<T> fromPage(IPage<T> page) {
        PageVO<T> vo = new PageVO<>();
        vo.setRecords(page.getRecords());
        vo.setTotal(page.getTotal());
        vo.setPages(page.getPages());
        vo.setCurrent(page.getCurrent());
        vo.setSize(page.getSize());
        return vo;
    }
}
```

### 16.3 查询与组装

```java
public List<CommentVO> getCommentsByNewsId(Long newsId) {
    // 1. 查询一级评论（parent_id IS NULL）
    List<Comment> topComments = commentMapper.selectTopCommentsByNewsId(newsId);

    // 2. 为每个一级评论查询回复
    for (Comment comment : topComments) {
```

### 16.4 两种嵌套方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|

| **无限级嵌套** | 灵活，支持深层讨论 | 查询复杂，性能较差 |

## 十七、树形结构构建算法

### 17.1 应用场景

- 新闻分类（一级分类 → 二级分类）
- 评论回复（评论 → 回复）
- 组织架构（部门 → 子部门）

### 17.2 Stream API 分组构建

```java
public List<Category> buildTree(List<Category> allCategories) {
    // 1. 按 parentId 分组
    Map<Long, List<Category>> parentIdMap = allCategories.stream()
            .filter(c -> c.getParentId() != null)
            .collect(Collectors.groupingBy(Category::getParentId));

    // 2. 筛选一级分类（parentId 为 null）
    List<Category> rootCategories = allCategories.stream()
            .filter(c -> c.getParentId() == null)
            .collect(Collectors.toList());

    // 3. 为每个一级分类设置子分类
    for (Category root : rootCategories) {
        root.setChildren(parentIdMap.getOrDefault(root.getId(), new ArrayList<>()));
    }

    return rootCategories;
}
```

### 17.3 递归构建（支持无限级）

```java
public List<Category> buildTreeRecursive(List<Category> all, Long parentId) {
    return all.stream()
            .filter(c -> Objects.equals(c.getParentId(), parentId))
            .peek(c -> c.setChildren(buildTreeRecursive(all, c.getId())))
            .collect(Collectors.toList());
}

// 调用
List<Category> tree = buildTreeRecursive(allCategories, null);
```

### 17.4 性能优化

| 方法 | 时间复杂度 | 适用场景 |
|------|------------|----------|
| 分组构建 | O(n) | 两级结构 |
| 递归构建 | O(n²) 最坏 | 多级结构 |
| 预排序 + 遍历 | O(n log n) | 大数据量 |

## 十八、软删除 vs 硬删除

### 18.1 概念

| 类型 | 操作 | 特点 |
|------|------|------|
| **硬删除** | `DELETE FROM table WHERE id = ?` | 数据彻底删除 |
| **软删除** | `UPDATE table SET status = 0 WHERE id = ?` | 数据保留，标记为已删除 |

### 18.2 本项目实现

评论模块使用软删除：

```java
public void deleteComment(Long commentId, Long operatorId, Integer operatorRole) {
    Comment comment = commentMapper.selectById(commentId);

    // 权限验证...

    // 软删除（修改状态）
    comment.setStatus(Comment.STATUS_HIDDEN);
    commentMapper.updateById(comment);
}
```

### 18.3 软删除优点

1. **数据可恢复**：误删可以恢复
2. **审计追踪**：保留操作记录
3. **外键安全**：不会破坏关联数据

### 18.4 软删除查询过滤

```java
// 查询时自动过滤已删除数据
List<Comment> comments = commentMapper.selectList(
    new LambdaQueryWrapper<Comment>()
        .eq(Comment::getStatus, Comment.STATUS_VISIBLE)
);
```
